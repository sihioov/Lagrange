# R4-01 — 가격수익률 백테스트 계약 제안 v1

상태: **PROPOSED / Owner 미승인 / 구현 미착수**. 작성일: 2026-10-23.
제안 버전: `owner-beta-price-only-simulation-v1-draft-1`.
이 문서는 [로드맵 R4-01](../../ROADMAP.md)의 결정안이며,
[기존 P0](2026-08-28-owner-beta-backtest-p0-owner-decision.md)의 미정 12항목을 채운다.
기존 승인란을 대신 체크하거나 R2/R3의 미완료 인수를 완료 처리하지 않는다.

## 검토할 제안

승인된 과거 ETF 데이터로 **기존 50일·200일 이동평균 전략과 069500 매수 후 보유**를 먼저 비교한다.
신호는 종가까지의 정보로 만들고 다음 거래일 시가에 매매한다. 초기자금은 1천만 원,
수량은 정수 주, 남는 돈은 무이자 현금이다. 비용은 **매수·매도 각각 거래금액의 0.1%라는 가정**과
비용 없는 기준 결과를 함께 계산한다. 이 값은 실제 증권사 수수료나 세율 주장이 아니다.

배당을 포함하지 않는 가격수익률 검증이다. 첫 버전에는 연환산·Sharpe 등 지표와 분할이 있는
데이터의 원장 처리를 넣지 않는다. 이렇게 제한해도 입력·신호 일치, 체결·현금·비용, 결과 재현성을
검증하고 다음 전략으로 확장할 기반을 만들 수 있다.

R2의 9월 이후 미승인 데이터나 실시간 수신을 기다리지 않고 이 결정안과 승인 후 구현을 진행할 수 있다.
R4 최종 출시의 R1/R2 의존성과 R4-04~06 검증은 유지한다. 새 수집·Paper·실거래 권한은 생기지 않는다.

## 세부 계산 규칙

### P0-01~02: 관측 구간과 신호

검증된 artifact의 세션을 오름차순 `d[0]..d[2451]`로 둔다. 단순 평일 목록을 새 달력으로 만들지 않는다.
기본 시작일 `S=d[200]`, 종료일 `E=d[2451]`: 200개 준비 세션과 2,252개 평가 세션이다.
사용자가 범위를 줄일 경우 S/E는 그 세션 목록의 정확한 날짜여야 하며, S 앞에 200세션 이상,
S~E에 평가 세션 2개 이상이 있어야 한다. 범위 밖·역순·준비 부족이면 enqueue 전에 거절한다.

첫 목표는 `T=prev(S)`에서 계산한다. 각 T에서 기존 추천 계산에 T 이하의 가격만 제공하고
전략·팩터 정의·snapshot·목표의 기존 무결성을 검증한다. 팩터는 기존 코드의 산술을 그대로 사용한다.
별도 근사 SMA나 새로운 반올림·허용오차로 추천과 다른 신호를 만들지 않는다.
전략 목표는 069500 100%/현금 0% 또는 그 반대이고 나머지 10종목 목표는 0이다.

S~E의 각 시가에는 직전 세션에 확정된 목표만 유효하다. 직전 목표와 같으면 매매하지 않는다.
첫날에는 초기 현금 상태와 비교한다. 매수 뒤 남은 현금으로 주가 하락 때 추가 매수하지 않으며,
최소 비중 변화나 금액 임계값은 따로 두지 않는다. 100%↔0% 전환만 체결 이벤트다.
체결 시가를 수량·비용·현금 가능성 계산에 사용하는 것은 허용하지만 신호 계산으로 되돌려 보내지 않는다.

기존 보유분은 전일 종가부터 다음 시가까지 보유한다. 체결 후에는 해당일 종가까지 보유한다.
E 종가에 평가하고 종료하며 강제 청산·그에 따른 비용은 없다. E의 새 신호는 계산하지 않는다.
warm-up 기간의 수익·체결·비용은 결과에 포함하지 않는다.

### P0-03~07: 가격·수량·비용 원장

가격과 금액의 최소 단위는 0.0001원이다. 입력 가격을 이 단위로 **정확히** 표현할 수 없으면 거절하며,
입력 가격을 반올림해 받아들이지 않는다. 수량은 음이 아닌 정수이고 checked arithmetic의 overflow는 실패다.
신호에는 adjusted close, 체결에는 raw open, 평가에는 raw close를 쓴다.
승인된 전체 구간의 모든 OHLC에서 raw와 adjusted의 수치가 같고 비현금 action이 0임을 사전 검증한다.
이는 v1의 좁은 적용 조건이며 일반적인 분할 처리가 구현됐다는 뜻이 아니다.

검증된 Stage5/승인 artifact의 세션 목록과 행을 대조한다. 전체 시장 세션, 한 ETF의 행, 필요한 시가·종가가
빠지거나 중복되면 실패한다. 달력을 행에서 다시 만들어 결손을 숨기거나 전일 값을 복사하지 않는다.
가격은 양수여야 한다. 실제 체결이 필요한 종목의 그날 raw volume이 0이면 매매 가능성을 가정하지 않고
전체 실행을 실패시킨다. 양수 거래량도 시가에서 전량 체결 가능함을 증명하지는 않는다.
이 시뮬레이션은 시가 체결을 가정하며 거래량 비례 제한·가격충격·부분 체결은 모델링하지 않는다.

운영 요청의 초기자금은 정확히 `10000000.0000` KRW로 고정한다. 테스트의 작은 합성 원장만 다른 자금을
사용할 수 있고, 그 테스트 결과는 실제 성과로 표시하지 않는다. 현금 이자·추가 입출금·배당·대차는 없다.
100% 목표로 전환하면 매수 원금+비용이 현재 현금 이하인 **가장 큰 정수 q**를 산출한다.
q가 0이면 매매 없이 현금을 보존하고 수량 부족 이유를 남긴다. 목표가 계속 100%면 재시도하지 않는다.
0% 목표로 전환하면 전량 매도한다. 일반 실행 순서는 매도→매수지만 첫 전략은 단일 종목 전환뿐이다.
음수 현금·음수 수량·체결 후 원장 불일치는 부분 결과 없이 실패한다.

두 비용 프로필을 같은 입력으로 독립 실행하며 각각 결과 해시를 갖는다.

| 프로필 | 매수·매도 각각의 통합 가정 비용 | 최소 비용 | 별도 세금 | 가격 슬리피지 |
| --- | --- | --- | --- | --- |
| `ILLUSTRATIVE_10BP_PER_SIDE_V1` (기본 표시) | 거래 원금 × 1/1000 | 0 | 0 | 0 |
| `ZERO_COST_REFERENCE_V1` (비교 표시) | 0 | 0 | 0 | 0 |

이것은 수수료·세금·시장충격을 실제로 추정한 표가 아니다. 프로필은 전체 기간에 적용하는 고정 가정이며
실제 수수료 유효일을 주장하지 않는다. 비용 입력 누락·다른 프로필·암묵적 fallback은 거절한다.
원금 `n=q×raw_open`은 정확히 계산한다. 기본 프로필의 비용은 `ceil(n/1000, 0.0001원)`이고
매수는 현금에서 `n+비용`을 빼고, 매도는 `n-비용`을 더한다. 주문당 한 번 부과하며 비용을 가격에
다시 더하지 않는다. 종가 NAV는 `현금 + q×raw_close`; 체결 전 NAV는 `현금 + q×raw_open`이다.

### P0-08~10: 비교·회전율·날짜

벤치마크는 전략과 별도 원장으로 S 시가에 같은 초기자금으로 069500을 비용 포함 최대 정수 주 매수하고
E 종가까지 보유한다. 같은 비용 프로필끼리만 전략과 비교한다. 현금·결손·분할 거절·평가 규칙도 같다.
첫 매수 뒤 재조정·잔여 현금 추가 매수·마지막 청산은 없다. 기준 자산은 총수익 지수로 대체하지 않는다.

각 평가일의 회전율은 `t_d=(매수 원금+매도 원금)/(2×그날 체결 전 NAV)`다.
거래가 없으면 0. 기간 회전율은 정확한 일별 분수를 합산한 뒤 최종 반올림한다.
첫 매수와 중간 전량 매도를 포함하고, 초기 현금 입금·수수료·없는 최종 청산은 포함하지 않는다.
연환산하지 않으며 화면에는 “기간 회전율(매매 원금 합계/2 기준)”이라고 설명한다.

결과에는 `session_date`와 `phase`만 쓴다. 순서는 `INITIAL_CASH`(S에 1회), `PRE_OPEN_MARK`,
`SELL`, `BUY`, `CLOSE_MARK`, `SIGNAL_FOR_NEXT_SESSION`이다. 매매 없는 단계는 빈 목록이고,
마지막 SIGNAL 단계는 생략한다. 최초 신호는 prev(S)의 날짜로 별도 저장한다.
같은 날짜·단계 안에서는 instrument ID 오름차순이다. Asia/Seoul은 날짜의 시장 맥락일 뿐,
실제 09:00/15:30 체결 시각이나 `acquired_at` 기반 시각을 만들지 않는다.

### P0-11: 허용 지표와 산술

`V0`는 S 시가 전 초기자금, `V_d`는 비용 반영 후 일별 종가 NAV다. 모든 분모는 양수여야 한다.
일별 NAV·현금·수량·체결 원금·비용·목표·신호 계보는 지표 산출의 원장으로 함께 보관한다.
전략과 벤치마크 각각에 아래 허용 목록만 제공한다.

| 결과 | 정확한 정의·단위 |
| --- | --- |
| 일별 수익률 | 첫날 `V_S/V0-1`, 이후 `V_d/V_prev(d)-1`; 비율 |
| 기간 수익률 | `V_E/V0-1`; 비율. 반올림한 일별 수익률을 곱해서 만들지 않음 |
| 최종 자산·현금·보유수량 | E 종가 NAV와 현금(KRW), 종목별 정수 주 |
| 누적 비용·매수/매도 원금 | 실제 기록된 각 항목의 정확한 합(KRW) |
| 최대낙폭 | `max_d(1-V_d/max(V0,V_S..V_d))`; 0 이상인 손실 비율. 시가·장중 낙폭은 주장하지 않음 |
| 기간 회전율 | 위의 `sum(t_d)`; 비율, 연환산 없음 |
| 체결 수 | 수량이 양수인 매수·매도 이벤트의 개수; 정수 |
| 벤치마크 대비 차이 | 전략 기간 수익률 − 같은 프로필 벤치마크 기간 수익률; 비율 차이, 화면은 퍼센트포인트 |

가격·금액은 소수 4자리 문자열, 수량·개수는 정수, 목표 비중은 기존 ppm 정수(합 1,000,000)다.
비율은 정확한 분수에서 **소수 12자리 ties-to-even**으로 최종 표시·직렬화하며 음의 0은 0으로 정규화한다.
판정·누적 원장은 표시 반올림 값을 재사용하지 않는다. UI의 퍼센트/퍼센트포인트는 그 비율에 100을 곱해
소수 2자리 ties-to-even으로 표시하고 원래 12자리 비율은 결과에 보존한다.

최소 표본은 평가 세션 2개다. 거래 0건이면 체결 수·비용·회전율은 0이고 현금 원장으로 수익률 0을 계산한다.
분모 0·관측 누락·overflow는 `null` 성과 대신 실행 실패다. 허용 목록 밖의 CAGR, 연환산 변동성,
Sharpe, Sortino, 승률, 거래별 수익률, 월별 지표는 v1 결과에 넣지 않는다. 따라서 연환산 일수나
무위험수익률의 숨은 기본값도 없다. 화면에 없는 지표를 0이나 `null`로 꾸며 내지 않는다.

항상 `OWNER_ONLY`, `PRICE_RETURN_ONLY`, `vendor_snapshot=true`, `strict_pit=false`와 비용 가정을 표시한다.
배당 총수익·실제 운용 수익·엄격한 PIT·실제 장중 체결 기록으로 설명하지 않는다.

### P0-12: 결과 해시의 정규 입력

결과별 `result_content_sha256`은 다음 필수 내용 전체를 포함한다. 아래 이름의 하위 필드까지 구현 시
폐쇄형 schema로 만들고, 빠진 값·알 수 없는 필드는 거절한다. 이 문서가 승인되면 승인된 문서의 정확한
바이트 SHA-256을 계약 pin으로 별도 고정한다. 자기 해시를 그 문서 안에 쓰는 순환 정의는 사용하지 않는다.

| 필수 영역 | 포함할 내용 |
| --- | --- |
| `contract` | 이 계약 버전, 승인된 계약 문서 바이트 해시, 결과 schema 버전 `owner-beta-price-only-result-v1` |
| `input` | 정확한 5개 pin, bars 바이트 해시, 승인 범위·11종목·세션 수, 고정된 네 가지 증거 label |
| `engine` | 실제 구현의 전체 Git commit, 실행 binary 바이트 해시, 빌드 toolchain/target/profile 식별자. 문서 HEAD나 현재 운영 앱을 엔진으로 대신 넣지 않음 |
| `strategy` | 정확한 ID/version/config, 동결 strategy snapshot 해시, 기존 팩터 정의 버전·해시. 첫 전략 외의 설정 거절 |
| `schedule` | 실제 S/E, 준비 구간 날짜 목록, 신호→체결 날짜 쌍, 모든 평가일 목록, date-only phase 순서 |
| `conventions` | 초기자금·화폐/수량/비율 scale·반올림, 매매·현금·가격·분할 거절·결손·종료·비용·벤치마크·회전율·지표 규칙의 명시 값 |
| `signals` | 각 T의 factor snapshot 해시·target snapshot 해시, 11종목 목표 ppm·현금 ppm. 기존 snapshot 해시를 다시 근사 계산하지 않음 |
| `strategy_ledger`, `benchmark_ledger` | 초기자금, 모든 날짜별 단계·수량·현금·원금·비용·NAV·미체결 사유, 허용 지표 전체 |

정규 JSON 규칙: UTF-8, BOM·공백·개행 없음, 객체 키는 ASCII 바이트 오름차순, 중복 키 금지.
제어 필드/값은 ASCII identifier·ISO `YYYY-MM-DD`·소문자 SHA-256으로 제한한다.
hash 값은 `sha256:` 접두어와 64자리 소문자 hex, Git commit은 전체 40자리 소문자 hex다.
소수는 위 scale의 문자열로만 표현한다(지수·`+`·불필요한 정수부 선행 0·음의 0 금지).
정수 JSON 값은 10진수 정규 표현, boolean은 `true/false`; nullable 필드는 없다.
배열은 날짜→phase→instrument 순서, 계보 목록은 해당 날짜 순서, 단순 종목 목록은 ID 순서로 고정한다.
기존 factor/strategy snapshot 내부에 있는 float를 이 JSON으로 재직렬화하지 않고 검증된 기존 해시로 묶는다.

이 정규 바이트에 SHA-256을 적용한다. 결과 해시 자체, job/request ID, enqueue/완료 시각, 실행 시간,
호스트/파일 경로, 로그, 번역된 화면 문구는 제외한다. Owner ID도 계산 내용에서 제외해 같은 승인 입력의
결과가 재현되게 하되, **권한은 별도의 owner-scoped job/result 저장·RLS로 강제**한다.
해시를 아는 것만으로 다른 Owner 결과를 조회·재사용할 수 없고, tenancy 검증은 R4-04/05의 필수 조건이다.
실행 중간의 원장을 성공 결과로 게시하지 않는다. 두 프로필 중 하나라도 실패하면 비교 화면은 성공으로
노출하지 않으며, 성공한 단일 결과의 존재로 쌍 전체 성공을 대신하지 않는다.

## 구현 후 반드시 대조할 작은 기준값

다음은 **합성 원장 예제**이며 실제 데이터나 성과가 아니다. 200세션 신호 계산을 생략할 수 있는
단위 검증에만 이미 확정된 목표를 공급한다. 통합 검증은 실제 200종가와 기존 snapshot 경계를 거쳐야 한다.
초기자금 1,000원, 첫날 목표 매수·시가 100/종가 110, 둘째 날 목표 현금·시가/종가 120,
각 체결일 거래량은 충분한 양수, 기본 0.1% 비용 가정이다.

| 단계 | 수량 | 현금(KRW) | 비용(KRW) | 평가 자산(KRW) |
| --- | --- | --- | --- | --- |
| 첫날 9주 매수 | 9 | 99.1000 | 0.9000 | 종가 1089.1000 |
| 둘째 날 9주 매도 | 0 | 1178.0200 | 1.0800 | 종가 1178.0200 |
| 벤치마크 둘째 날 보유 | 9 | 99.1000 | 추가 0 | 종가 1179.1000 |

전략 기간 수익률 `0.178020000000`, 벤치마크 `0.179100000000`, 차이 `-0.001080000000`
(−0.108퍼센트포인트), 전략 누적 비용 1.9800원. 0비용 프로필은 10주로 시작하고 둘째 날 두 원장 모두
1,200원, 수익률 20%다. 이 차이는 비용이 수량에도 영향을 준다는 검사 기준이다.

추가 필수 검증: 합성 fixture에서 T 이후 가격만 바꾸면 T의 팩터 수치·목표 비중은 같음
(전체 artifact pin 변경에 따른 계보 해시 차이는 정상이며 해시 동일성을 요구하지 않음); 동률은 현금;
목표 불변이면 잔여 현금 추가 매수 없음; 최종일 강제 매도 없음; 분할/조정 불일치·결손·pin 변조 거절;
비용 올림·최대 정수 수량·overflow; 실행 ID/시각 변화에는 같은 결과 해시;
비용·일정·신호·원장 변조에는 다른 해시; 다른 Owner 접근 거절.
