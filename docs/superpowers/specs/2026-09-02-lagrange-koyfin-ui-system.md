# Lagrange Station 전체 Koyfin형 UI/UX 시스템 요구사항

작성일: 2026-09-02
상태: 확정
대상: 모든 인증 후 Lagrange Station 화면

## 1. 범위 정정

Koyfin형 룩앤필은 Stock Beta 전용 테마가 아니라 서비스 전체의 공통 디자인 시스템이다.
사용자가 좌측 메뉴로 이동할 때 이전 Lagrange 셸, 밝은 테마, 큰 둥근 카드 또는 넓은 소개형
레이아웃으로 돌아가는 결과는 결함이다.

Stock Beta의 데이터 중심 3패널 구성은 해당 제품의 정보 구조이며 모든 페이지가 같은 패널 수를
복제할 필요는 없다. 대신 모든 제품이 동일한 셸, 색상 토큰, 밀도, 패널 위계, 표·폼·상태 표현,
반응형 규칙을 사용해야 한다.

## 2. 대상 화면

- `/`: 연구 대시보드
- `/strategies`: 전략
- `/recommendations`: 추천
- `/candidates`: 일일 후보 종목
- `/screener`: 종목 스크리너
- `/backtests`: 백테스트
- `/paper`: 모의투자 계좌
- `/stock-beta`와 `/stock-beta/[instrument]`: 종목 신호 베타
- `/stocks/[instrument]`: 종목 분석
- `/admin`: 운영 관리
- `/live`: 실거래 제어
- 위 경로의 loading, empty, blocked, error 상태

로그인·콜백처럼 인증 전 또는 프로토콜 전용 경로는 이번 공통 연구 셸 대상이 아니다.

## 3. 공통 셸 계약

- 모든 인증 화면은 하나의 실제 터미널 셸 트리를 사용한다. 숨겨진 레거시 셸이나 제품별 중복
  `<main>`·내비게이션을 만들지 않는다.
- 데스크톱은 48~52px 상단 유틸리티 바, 약 210~220px 좌측 레일, 나머지 본문으로 구성한다.
- 상단에는 Lagrange 브랜드, 현재 제품 문맥, 역할, 비공개/읽기 전용 상태 및 언어 전환만 둔다.
- 현재 경로는 실제 메뉴명으로 표시한다. Stock Beta에서만 실제 검색·기준일 슬롯을 표시한다.
- 메뉴 목적지, Owner/Member 가시성, 로그아웃, locale, skip link와 권한 경계는 보존한다.
- 기준 테마는 짙은 흑청색 터미널이다. 메뉴 이동 중 밝은 레거시 테마로 전환되지 않는다.
- 작동하지 않는 알림, 내보내기, 위젯 추가, 레이아웃, 시장 상태 버튼을 만들지 않는다.

## 4. 공통 시각 언어

- 캔버스·사이드바·패널·패널 헤더의 네 단계 어두운 표면을 사용한다.
- 패널 간격은 6~8px, 경계는 1px, 반경은 4px 이하이며 그림자와 그라디언트를 사용하지 않는다.
- 제목, 메타데이터, 표 헤더와 숫자에는 모노스페이스 계열을 제한적으로 사용한다.
- 청색은 선택과 상호작용, 녹색·적색·황색은 명시적 상태에만 사용한다.
- `RoutePage`, Surface Panel, State Panel, Data Report, Data Table, 폼과 액션은 공통 토큰을
  상속한다. 제품 컴포넌트가 별도 레거시 카드 토큰을 다시 선언하지 않는다.
- 페이지 설명은 짧은 보조 문맥으로 유지하고 첫 화면을 대형 소개문이 차지하지 않는다.
- 표와 폼은 데이터 밀도를 높이되 모든 주요 포인터 대상은 최소 44px을 유지한다.

## 5. 제품별 정보 구조

- 대시보드는 각 워크스페이스의 상태와 진입점을 스캔할 수 있는 고밀도 런처로 표현한다.
- 전략·추천·후보·스크리너·백테스트·Paper는 기존 데이터와 작업 순서를 유지하면서 공통 패널,
  테이블, 필터 및 작업 바를 사용한다.
- Stock Beta는 기존 하위 명세의 순위/프로필/분해/매트릭스/스냅샷 위젯 구조를 유지한다.
- Admin과 Live는 빈 상태나 안전 제어만 존재해도 동일 셸과 상태 패널 언어를 사용한다.
- 현재 API가 제공하지 않는 시장 데이터, 차트, 가격, 뉴스 또는 상태를 장식 목적으로 만들지 않는다.

## 6. 구조와 확장성

- 공통 셸과 토큰은 `components/shell` 및 전역 디자인 프리미티브가 소유한다.
- 새 메뉴는 중앙 내비게이션 정의에 항목을 추가하고 공통 셸을 자동 상속해야 한다.
- 제품 페이지는 셸을 직접 복제하거나 전역 토큰을 덮어쓰지 않는다.
- 데이터 위젯은 중앙 registry/layout 설정으로 추가·제거·순서를 바꿀 수 있고 직접 fetch하지 않는다.
- 공통 패널과 상태 프리미티브는 의미·접근성 계약을 유지한 채 재사용한다.
- Server Component가 데이터와 권한을 소유하고, Client Component는 필요한 상호작용 경계에만 둔다.

## 7. 보존 조건

- API, DTO, 백엔드, 인증 정책, KIS/OpenDART, 데이터 파이프라인을 변경하지 않는다.
- 서버 순서, 숫자, provenance, 경고, fail-closed 상태를 변경하거나 합성하지 않는다.
- Owner 전용 메뉴와 데이터는 Member DOM에 렌더링하지 않는다.
- 주문·계좌 실거래 경계와 모든 저장소 안전 정책을 그대로 유지한다.

## 8. 반응형·접근성

- 1280×720과 1440×900에서는 고정 좌측 레일과 본문 단독 스크롤을 사용한다.
- 768px 이하에서는 상단 바, 가로 스크롤 가능한 메뉴, 본문, 로그아웃 순으로 자연스럽게 재배치한다.
- 375×812, 768×1024, 1280×720, 1440×900 및 200% 확대에서 페이지 전체 가로 넘침이 없다.
- 하나의 `h1`, 하나의 `main`, 명명된 Primary nav, skip link, 키보드 포커스, forced colors,
  reduced motion과 WCAG 2.2 AA 대비를 유지한다.

## 9. 완료 판정

- 어떤 메뉴 사이를 이동해도 `research-terminal` 또는 Stock Beta 확장형 터미널 셸만 존재한다.
- 모든 대상 경로에서 동일한 캔버스, 상단 바, 좌측 레일, 패널 경계·반경·밀도를 확인할 수 있다.
- Stock Beta 검색·선택·필터와 다른 제품의 기존 폼·링크·표 동작이 유지된다.
- 단위 테스트, 타입 검사, 린트, 프로덕션 빌드와 전체 Playwright 회귀가 통과한다.
- 외부 확인용 데모에서 HTML뿐 아니라 모든 CSS/JavaScript 번들이 200이며 메뉴 이동 후에도
  같은 룩앤필이 유지된다.
