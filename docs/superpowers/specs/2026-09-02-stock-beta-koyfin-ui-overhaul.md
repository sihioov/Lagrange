## 0. 재작성 배경과 판정

2026-09-01 명세는 기존 전역 셸과 디자인 토큰 보존을 우선했다. 그 결과 기존 Lagrange 화면에
다크 팔레트와 모듈형 위젯을 추가한 결과도 명세를 충족하는 것으로 판정될 수 있었다. 해당 결과는
Koyfin형 UI 개편으로 인정하지 않는다.

이번 명세에서 말하는 Koyfin형 개편은 색상 변경이 아니다. 다음 다섯 가지가 함께 바뀌어야 한다.

1. 애플리케이션 셸과 화면 골격
2. 정보 밀도와 공간 사용 방식
3. 패널 구성과 시각적 위계
4. 종목 선택을 중심으로 한 워크스페이스 상호작용
5. 숫자, 표, 상태 및 근거를 표현하는 터미널형 시각 언어

현재 구현의 데이터 계약, 권한 경계, 테스트 자산 및 위젯 레지스트리는 재사용할 수 있다. 그러나
현재의 일반 앱 셸, 큰 둥근 카드, 넓은 여백, 설명문 중심의 세로 흐름은 시각 기준으로 재사용하지
않는다.

## 1. 목표

- 종목 신호 베타를 Koyfin에서 영감을 받은 고밀도 시장 리서치 워크스페이스로 재설계한다.
- 1280px 이상 화면에서 순위 목록, 선택 종목 분석, 신호 분해 및 횡단면 요약을 동시에 비교하게 한다.
- 사용자가 전체 30종목을 스캔하고, 행을 선택하고, 근거를 확인하는 흐름을 한 화면에서 완료하게 한다.
- Koyfin의 상표, 로고, 문구 또는 독점 자산을 복제하지 않고 Lagrange 브랜드를 사용한다.
- 가격·거래량 연구 전용, Owner 전용, 읽기 전용이라는 제품 경계를 훼손하지 않는다.
- 위젯 추가·제거·교체·재배치를 코드와 설정만으로 수행할 수 있는 구조를 유지한다.

## 2. 기준 화면과 룩앤필 계약

### 기준 자료

- 1차 시각 기준: `docs/ui-concepts/koyfin.html`
- 공용 확인 URL: `https://l1nnx-sh.taild74a33.ts.net:8443/ui-concepts/koyfin`
- 스타일 기준: `docs/ui-concepts/concepts.css`의 `.koyfin-app`, `.k-*` 규칙

기준 화면의 가짜 데이터는 사용하지 않는다. 기준 화면에서 가져오는 것은 셸, 밀도, 패널 위계,
상호작용 패턴 및 시각 언어다.

### 반드시 닮아야 하는 요소

- 48~52px 높이의 얇은 상단 유틸리티 바
- 데스크톱에서 약 210~220px인 고정 좌측 리서치 내비게이션
- 상단 바 바로 아래의 한 줄 스냅샷 스트립
- 6~8px 간격의 고밀도 다중 패널 그리드
- 얇은 1px 경계, 2~4px 수준의 작은 모서리 반경, 그림자 없는 패널
- 작은 패널 헤더와 모노스페이스 숫자
- 좌측 순위 테이블, 중앙 선택 종목 분석, 우측 신호 분해의 3영역 구조
- 선택 행과 연결된 중앙·우측 패널의 즉시 갱신
- 하단의 횡단면 매트릭스와 스냅샷 근거 테이프
- 짙은 흑청색 배경, 청색 주 강조, 녹색·적색·황색 상태색

### 닮았다고 인정하지 않는 결과

다음 중 하나라도 해당하면 Koyfin형 완료로 판정하지 않는다.

- 기존 Lagrange 일반 셸이 그대로 보이고 본문 카드 색상만 어두워진 경우
- 큰 둥근 카드가 넓은 간격으로 세로 배치된 경우
- 정책 설명이나 소개 문구가 첫 화면의 주 콘텐츠를 차지하는 경우
- 순위 테이블과 선택 종목 분석을 동시에 볼 수 없는 경우
- 데스크톱 첫 화면이 일반 관리 대시보드 또는 랜딩 페이지처럼 보이는 경우
- Koyfin 기준 화면과 나란히 놓았을 때 색상 외의 공통 구조를 식별하기 어려운 경우

## 3. 범위

### 대상 화면

- `/stock-beta`: 종목 신호 워크스페이스
- `/stock-beta/[instrument]`: 종목 상세 근거 워크스페이스

### 포함

- Stock Beta 경로 전용 터미널 셸 변형
- 상단 바, 좌측 내비게이션, 스냅샷 스트립 및 본문 그리드 재구성
- 목록과 상세 화면의 패널 디자인 및 상호작용 개편
- Stock Beta 전용 시각 토큰
- 한국어·영어, 반응형, 접근성 및 오류 상태
- 모듈형 위젯 레지스트리와 레이아웃 설정

### 셸 경계

- Stock Beta 경로에서는 일반 Lagrange 셸의 시각 표현을 그대로 유지하지 않는다.
- 실제 메뉴 목적지, 권한 및 로그아웃 기능은 유지하되 Koyfin형 얇은 상단 바와 고밀도 좌측 레일로
  표현한다.
- 이 셸 변형은 Stock Beta 경로에만 적용한다.
- 대시보드, 전략, 추천, 스크리너, 백테스트 및 Paper 화면은 변경하지 않는다.

### 테마 결정

- 이번 개편의 기준 테마는 Koyfin형 다크 터미널이다.
- Stock Beta 경로는 전역 테마와 무관하게 완성된 다크 터미널 표현을 우선한다.
- 라이트 터미널 테마는 이번 완료 조건이 아니다.
- 다른 Lagrange 경로의 기존 라이트·다크 동작은 변경하지 않는다.
- Stock Beta에서 테마 전환을 제공하지 않는다면 작동하지 않는 테마 버튼을 표시하지 않는다.

## 4. 사용자·정책·데이터 경계

- Owner만 접근할 수 있고 Member에게는 메뉴와 데이터가 노출되지 않아야 한다.
- 고정된 30종목 관찰 목록만 사용한다.
- `BULLISH`, `NEUTRAL`, `BEARISH`는 조건 레이블이며 예측 확률이 아니다.
- 매수·매도, 목표가, 기대수익률, 포지션, 주문 또는 계좌 기능처럼 표현하지 않는다.
- 거래량과 거래대금은 체결 유동성이 아닌 활동성 프록시로 표현한다.
- 원주가 및 기업행사 왜곡 가능성을 항상 확인할 수 있어야 한다.
- 서버 순위, Top 5, 원본 숫자, 조건 및 provenance를 변경하지 않는다.
- UI가 재정렬, 재점수화, 정규화 또는 신호를 재판정하지 않는다.

### 사용할 수 있는 값

- 종목명, 종목 ID, 전체 순위, Top 5, 종합 점수, 조건
- 20·60·120일 수익률과 변동성
- 120일 최대 낙폭
- 20·60일 이동평균
- 20일 평균 거래량, 20/60 거래량 비율, 20일 평균 거래대금 활동성 프록시
- 상세 API의 팩터명, 원본 값, 해석 및 조건 판정 사유
- 기준일, 배치, 승인, 아티팩트, 스냅샷 및 정책 provenance
- 위 값에서 손실 없이 계산되는 종목 수와 조건별 개수

### 표시하거나 암시하면 안 되는 값

- 현재가, 1일 등락률, 실시간 시세 및 장 운영 상태
- KOSPI·KOSDAQ·환율·금리·시장 폭
- 가격 시계열, 캔들 또는 가짜 추세선
- 업종, 섹터, 뉴스, 기업 이벤트 및 신호 변경 이력
- 팩터의 문서화되지 않은 0~100 환산값
- 변경 시각, `NEW`, `UP`, `RISK` 등 이력 데이터가 있어야 성립하는 상태
- API가 제공하지 않은 값, 가짜 값 또는 장식용 합성 데이터

점수와 팩터 값은 계약상 유한 숫자일 뿐 고정 범위가 보장되지 않는다. 따라서 원형 게이지나 진행률
막대처럼 0~100 범위를 암시하는 표현을 사용하지 않는다. 범위를 시각화하려면 API 계약에 명시된
도메인 또는 화면에 공개된 산식이 먼저 있어야 한다.

## 5. Stock Beta 전용 셸

### 상단 유틸리티 바

- 높이는 48~52px로 유지한다.
- Lagrange 로고와 `MARKET RESEARCH` 또는 동등한 제품 문맥을 표시한다.
- 현재 응답에 포함된 종목의 종목명·종목 ID 검색 필드를 제공한다.
- `/` 키로 검색에 포커스할 수 있고 `Escape`로 닫거나 초기화할 수 있다.
- Owner, Read only 및 데이터 기준일을 짧은 상태로 표시한다.
- 실제 기능이 없는 Alerts, Export, Add widget 또는 Layout 버튼은 표시하지 않는다.

### 좌측 내비게이션

- 실제 Lagrange 메뉴와 권한을 사용한다. 기준 목업의 가짜 메뉴명을 복사하지 않는다.
- 데스크톱에서는 210~220px 폭으로 고정하고 현재 Stock Beta 항목을 청색 선과 짙은 선택 배경으로
  강조한다.
- 821~1100px에서는 약 52~56px 아이콘 레일로 축소한다.
- 820px 이하에서는 상단의 가로 스크롤 가능한 압축 내비게이션으로 전환하거나 메뉴 버튼으로 접는다.
- 둥근 대형 메뉴 카드와 넓은 세로 간격을 사용하지 않는다.

### 스냅샷 스트립

가짜 시장 전광판 대신 동일한 리듬의 실제 데이터 스트립을 사용한다.

- `AS OF`: 데이터 기준일
- `UNIVERSE`: 전체 또는 필터 결과 종목 수
- `BULLISH`: 정확한 종목 수
- `NEUTRAL`: 정확한 종목 수
- `BEARISH`: 정확한 종목 수
- `SNAPSHOT`: API의 `registration_status`, `publication_status`, `materialization_status`를 짧게 표현

각 셀은 44~50px 높이, 얇은 구분선, 짧은 레이블과 모노스페이스 값을 사용한다. 화면 폭이
부족하면 셀을 가로 스크롤하되 값을 숨기거나 두 줄 카드로 키우지 않는다.

성공 DTO에는 별도 무결성 상태 필드가 없다. 성공 화면에 `Integrity passed`, `Verified` 또는
동등한 합성 상태를 만들지 않는다. 무결성은 실제 `OWNER_BETA_EQUITY_SIGNALS_INTEGRITY_FAILED`
오류가 반환된 경우에만 실패 상태로 표시한다.

### 제목·도구 바

- 높이는 약 52~58px로 유지한다.
- 경로 문맥과 `KR Equity Signal Board`에 해당하는 현지화 제목을 표시한다.
- 우측에는 실제로 동작하는 필터 열기, 필터 초기화 및 열 보기 설정만 둔다.
- 긴 페이지 소개문은 이 영역에 넣지 않는다.

## 6. 메인 워크스페이스

### 데스크톱 그리드

1280px 이상에서는 다음 구조를 기본으로 한다.

```text
┌──────────────┬────────────────────────┬──────────────┐
│ 순위 보드    │ 선택 종목 신호 프로필 │ 신호 분해    │
│ 약 25%       │ 약 50%                 │ 약 25%       │
├──────────────┼────────────────────────┴──────────────┤
│ 조건 매트릭스│ 현재 스냅샷 근거 테이프              │
└──────────────┴───────────────────────────────────────┘
```

- 열 비율은 약 `0.8fr / 1.6fr / 0.75fr`을 기준으로 한다.
- 첫 행 높이는 최소 350px이며 일반적인 1280×720 화면에서 약 50~55vh를 사용한다.
- 두 번째 행 높이는 약 240~280px를 기준으로 한다.
- 패널 간격은 6~8px로 유지한다.
- 페이지 전체가 아닌 각 표·패널 내부에서 필요한 스크롤을 처리한다.

### A. 순위 보드

- 30종목 전체 순위를 한 패널 안에서 내부 세로 스크롤로 제공한다.
- 기본 열은 순위, 종목명·ID, 점수, 조건, 20일 수익률, 거래량 비율로 한다.
- Top 5는 서버가 반환한 데이터와 일치해야 하며 텍스트 또는 배지로 함께 표시한다.
- 행 높이는 데스크톱에서 약 34~40px로 유지한다.
- 숫자는 모노스페이스와 tabular numerals를 사용한다.
- 선택 행은 배경과 2px 청색 인셋 선으로 구분한다.
- 최신 응답의 초기 선택은 `top5[0]`이 전체 행에 존재하면 해당 종목, 그렇지 않으면 `rows[0]`으로
  한다. 필터 응답은 `rows[0]`을 사용하며 어느 경우에도 행 순서를 바꾸지 않는다.
- 마우스 클릭, `Enter`, `Space`로 선택할 수 있다.
- 선택만으로 상세 페이지로 이동하지 않고 중앙·우측 위젯을 갱신한다.
- 별도의 명확한 상세 링크 또는 동작으로 상세 화면에 이동한다.
- 부가 지표는 열 보기 설정 또는 행 상세 팝오버에서 접근 가능하게 한다.

### B. 선택 종목 신호 프로필

- 선택된 종목명·ID, 순위, 점수, 조건 및 기준일을 패널 헤더에 표시한다.
- 중심 시각화는 가격 차트가 아니라 실제 기간별 지표 비교다.
- `수익률`, `변동성`, `활동성` 탭 또는 세그먼트를 제공한다.
- 수익률은 20·60·120일 값을 0축 기준 막대 또는 점 플롯으로 비교한다.
- 변동성은 20·60·120일 값을 동일 단위 막대로 비교한다.
- 활동성은 평균 거래량, 거래량 비율 및 평균 거래대금 원본 값을 표시한다.
- 연결된 선 그래프로 세 기간을 시계열처럼 오인시키지 않는다.
- 이동평균과 최대 낙폭은 하단의 조밀한 핵심 수치 스트립으로 제공한다.
- 모든 시각화에는 정확한 원본 값을 텍스트로 함께 표시한다.

### C. 신호 분해

- 종합 점수는 큰 숫자로 표시하되 백분율이나 확률로 표현하지 않는다.
- 조건은 텍스트와 상태색을 함께 사용한다.
- 현재 목록 API에서 제공하는 수익률, 변동성, 낙폭 및 활동성 핵심값을 조밀한 행으로 보여준다.
- 값의 범위가 보장되지 않은 지표에는 진행률 막대나 원형 게이지를 사용하지 않는다.
- `BETA`, `READ ONLY` 상태를 작은 배지로 표시한다.
- 선택된 종목이 바뀌면 전체 패널이 즉시 같은 종목으로 갱신되어야 한다.

### D. 조건 매트릭스

- 기준 목업의 히트맵 리듬을 실제 30종목 스냅샷으로 대체한다.
- 서버 순서대로 종목 타일을 배치하고 조건에 따라 녹색·중립색·적색을 사용한다.
- 각 타일에는 종목 ID 또는 짧은 종목명과 정확한 점수를 표시한다.
- 색상만으로 상태를 전달하지 않고 조건 약어 또는 접근 가능한 레이블을 제공한다.
- 타일 선택은 순위 보드 선택과 동기화한다.
- 면적 크기로 값의 크기를 암시하는 treemap은 사용하지 않는다.

### E. 현재 스냅샷 근거 테이프

- 신호 변경 이력처럼 보이는 시간순 테이프를 만들지 않는다.
- 현재 응답의 Top 5 또는 현재 필터 결과 상위 행을 서버 순서로 표시한다.
- 각 행은 순위, 종목 ID, 조건, 점수 및 실제 핵심 지표 하나를 표시한다.
- 제목에 `현재 스냅샷`임을 명시하고 `NEW`, 변경 시각 또는 변화 방향을 만들지 않는다.
- 필터 결과에서는 `Top 5`라고 부르지 않고 `현재 결과 상위`로 표시한다.

### 정책과 provenance

- 첫 화면 상단을 큰 정책 카드가 차지하지 않는다.
- 제목·도구 바 또는 스냅샷 스트립에 `Owner only · Read only · Original price` 요약을 항상 표시한다.
- 전체 정책 문구와 provenance는 하단의 접이식 패널 또는 우측 drawer에서 제공한다.
- 해시를 포함한 API 원본 provenance 필드는 누락하지 않는다.
- 무결성 실패, 데이터 차단 및 권한 거부 시에는 조밀한 레이아웃보다 실패 상태를 우선한다.

## 7. 필터와 검색

- 필터는 기본 워크스페이스를 밀어내는 큰 카드가 아니라 우측 drawer, 팝오버 또는 조밀한 패널로
  제공한다.
- 조건, 추세, 점수, 기간별 수익률·변동성, 낙폭 및 활동성 범위를 모두 유지한다.
- 적용 중인 필터는 제목·도구 바 아래 한 줄 칩으로 표시한다.
- 필터 칩은 개별 제거가 가능하고 전체 초기화를 제공한다.
- 기존 GET URL 계약을 유지한다.
- 필터 제출, 새로고침 및 상세 화면 왕복 후에도 문맥을 보존한다.
- 필터 결과가 0이면 패널 골격 안에서 명시적 빈 상태를 표시하고 이전 행을 남기지 않는다.
- 검색은 현재 응답의 종목만 대상으로 한다. 최신 화면에서는 최대 30종목, 필터 화면에서는 실제
  필터 결과만 검색하며 자동완성에 가짜 종목을 추가하지 않는다.

## 8. 종목 상세 워크스페이스

- 메인 화면과 동일한 상단 바, 좌측 레일 및 패널 시각 언어를 사용한다.
- 일반 RoutePage의 큰 제목과 세로 카드 흐름으로 되돌아가지 않는다.
- 상단 컨텍스트 바에 종목명·ID, 순위, 점수, 조건, 기준일 및 필터 보존 뒤로가기를 표시한다.
- 상세 화면의 스트립은 상세 API에 실제로 있는 `AS OF`, 순위, 조건,
  `registration_status`·`publication_status`·`materialization_status` 및 Read only 문맥으로
  구성한다. 조건별 전체 종목 수를 표시하기 위해 목록 API를 추가 호출하지 않는다.
- 데스크톱에서는 다음 세 영역을 동시에 제공한다.
  - 기간별 수익률·변동성·낙폭
  - 이동평균·거래량·활동성
  - 팩터 원본 값·해석과 조건 판정 사유
- 상세 API의 팩터 값은 임의 정규화하지 않고 원본 값과 해석을 함께 표시한다.
- 조건 판정 사유는 순서와 문구를 바꾸지 않는다.
- 전체 provenance와 정책은 접을 수 있지만 접근 경로를 숨기지 않는다.
- 존재하지 않는 종목, 데이터 차단 및 무결성 실패 시 이전 종목 데이터를 표시하지 않는다.

### 형태와 밀도

- 패널 반경은 2~4px, 입력과 버튼은 3~5px를 기준으로 한다.
- pill은 상태 배지와 필터 칩에만 제한적으로 사용한다.
- 카드 그림자, 유리 효과, 큰 그라디언트 및 장식용 광택을 사용하지 않는다.
- 본문 기본 크기는 12~13px, 패널 보조 레이블은 9~11px를 기준으로 한다.
- 페이지 제목은 15~18px 범위로 유지하며 랜딩 페이지형 대형 제목을 사용하지 않는다.
- 종목 ID, 순위, 점수, 날짜 및 수치는 모노스페이스와 tabular numerals를 사용한다.
- 패널 헤더 높이는 약 40~44px, 버튼 높이는 약 28~32px로 유지한다.
- 터치 환경에서는 실제 클릭 영역을 최소 44px로 확장하되 시각적 밀도는 유지한다.

## 10. 반응형

### 1280px 이상

- 전체 터미널 셸과 3열 메인 그리드를 표시한다.
- 1280×720 첫 화면에서 상단 바, 내비게이션, 스냅샷 스트립, 제목 바, 첫 행 전체와 두 번째 행
  일부가 보여야 한다.
- 큰 정책 카드나 소개문 때문에 핵심 표가 접힌 영역 아래로 내려가면 실패다.

### 821~1279px

- 좌측 내비게이션은 아이콘 레일로 축소한다.
- 순위 보드와 신호 프로필을 2열로 유지하고 신호 분해를 다음 행 전체 폭으로 이동한다.
- 조건 매트릭스와 근거 테이프는 데이터 우선순위에 따라 2열 또는 순차 배치한다.

### 820px 이하

- 상단 바를 압축하고 내비게이션을 가로 레일 또는 메뉴로 전환한다.
- 스냅샷 스트립은 가로 스크롤을 허용한다.
- 위젯은 한 열로 배치하되 순서는 `순위 → 선택 종목 프로필 → 신호 분해 → 매트릭스 → 근거`로 한다.
- 표는 내부 가로 스크롤을 사용하고 페이지 전체 가로 스크롤은 금지한다.
- 고정 요소가 콘텐츠나 마지막 행을 가리지 않아야 한다.

### 필수 검증

- 375×812
- 768×1024
- 1280×720
- 1440×900
- 브라우저 200% 확대

## 11. 위젯 아키텍처

- 데이터 조회, 제품 셸, 페이지 조립, 레이아웃 설정 및 위젯 표현을 분리한다.
- Stock Beta 전용 셸은 페이지 위젯과 분리된 레이아웃 컴포넌트로 구현한다.
- 각 위젯은 직접 API를 호출하지 않는다.
- 서버 페이지 또는 컨트롤러가 검증된 DTO를 view model로 전달한다.
- 서버가 결정한 순서와 원본 값을 view model 단계에서 바꾸지 않는다.
- 클라이언트 경계는 검색, 행 선택, 탭 및 drawer처럼 상호작용이 필요한 최소 범위로 제한한다.
- 클라이언트에 전달하는 props는 직렬화 가능한 DTO와 문자열·숫자·불리언으로 제한한다.
- 공통 `TerminalWidgetFrame`이 패널 헤더, 상태, 로딩, 오류 및 밀도를 통일한다.
- 중앙 레지스트리와 breakpoint별 레이아웃 설정으로 위젯을 조립한다.

```ts
type StockBetaWidgetDefinition = {
  id: string;
  region: "rank" | "primary" | "inspector" | "matrix" | "tape" | "evidence";
  component: React.ComponentType<SerializableWidgetProps>;
  required: boolean;
  defaultVisible: boolean;
  desktop: { order: number; span: number };
  tablet: { order: number; span: number };
  mobile: { order: number; span: number };
};
```

- 새 선택 위젯은 컴포넌트 추가와 레지스트리 등록만으로 노출할 수 있어야 한다.
- 위젯 제거가 페이지 JSX 재작성이나 다른 위젯 수정으로 이어지지 않아야 한다.
- 필수 위젯은 순위, 정책 요약, 실패 상태 및 provenance 접근 영역이다.
- 사용자 드래그앤드롭, 개인별 레이아웃 저장 및 실제 `ADD WIDGET` UI는 이번 범위가 아니다.

## 12. 접근성 및 상호작용

- WCAG 2.2 AA 대비를 충족한다.
- 페이지당 `h1`은 하나이고 landmark와 제목 순서가 논리적이어야 한다.
- 표 caption, 행·열 헤더 및 선택 상태를 보조기기에 전달한다.
- 순위 행과 매트릭스 타일은 동일한 선택 상태를 공유한다.
- 키보드로 검색, 필터, 행 선택, 탭, 상세 링크 및 provenance에 접근할 수 있어야 한다.
- `:focus-visible`은 청색 또는 고대비 외곽선으로 명확하게 표시한다.
- 상태는 색상과 텍스트를 함께 사용한다.
- reduced motion과 forced colors를 지원한다.
- 200% 확대에서 값이나 조작 기능이 손실되지 않아야 한다.
- 로딩, 빈 결과, 오류 및 선택 변경을 필요한 범위에서 보조기기에 전달한다.

## 13. 실패 및 빈 상태

다음 상태를 서로 구분한다.

- 로그인 필요
- Owner 권한 없음
- 데이터 사용 불가
- 스냅샷 무결성 실패
- 잘못된 필터
- 필터 결과 없음
- 종목을 찾을 수 없음
- 일반 API 오류

실패 시 신호 행을 표시하거나 오래된·합성 데이터로 대체하지 않는다. 터미널 셸은 유지할 수 있지만
중앙 데이터 영역에는 원인과 실제 복구 방법만 표시한다. 오류 화면이 이전 성공 응답의 숫자를
잔상처럼 남겨서는 안 된다.

## 14. 시각 수용 기준

기능 테스트 통과만으로 완료 처리하지 않는다. 다음 시각 검수를 모두 통과해야 한다.

### 1280×720 필수 체크리스트

- [ ] 상단 바 높이가 약 50px이며 일반 앱의 큰 헤더가 보이지 않는다.
- [ ] 좌측에 고밀도 내비게이션 레일이 보인다.
- [ ] 실제 데이터로 구성된 한 줄 스냅샷 스트립이 보인다.
- [ ] 순위, 선택 종목 프로필 및 신호 분해가 첫 행에서 동시에 보인다.
- [ ] 패널 간격이 6~8px이고 패널 반경이 4px 이하로 보인다.
- [ ] 큰 소개문, 큰 정책 카드 및 과도한 빈 공간이 없다.
- [ ] 첫 화면에서 최소 6개 이상의 순위 행을 스캔할 수 있다.
- [ ] 중앙 패널에 실제 기간별 지표 시각화와 정확한 숫자가 함께 보인다.
- [ ] 하단 매트릭스 또는 근거 테이프 일부가 접힌 영역 위에 보인다.
- [ ] 기준 Koyfin 콘셉트와 색상 외에도 셸·그리드·밀도·패널 위계가 대응한다.

### 비교 검수

- 기준 콘셉트와 구현 화면을 같은 1280×720 viewport로 캡처한다.
- 두 이미지를 나란히 검토한다.
- 리뷰어가 `상단 바`, `좌측 레일`, `스냅샷 스트립`, `3패널 첫 행`, `하단 보조 행`을 각각
  대응시킬 수 있어야 한다.
- “기존 화면에 다크 테마만 적용했다”는 판정이 나오면 자동 실패다.
- 데스크톱과 모바일 스크린샷은 PR 또는 QA 산출물에 남긴다.

## 15. 기능 및 품질 완료 기준

- 기존 API 계약, 인증 및 Owner 권한 경계를 변경하지 않는다.
- 최신 응답의 서버 Top 5와 전체 30종목에 접근할 수 있다.
- 필터 결과에서는 실제 결과 수와 `현재 결과 상위` 문구를 사용한다.
- 모든 필터와 URL 문맥 보존이 동작한다.
- 목록 선택, 매트릭스 선택 및 분석 패널이 같은 종목으로 동기화된다.
- 상세 화면에서 모든 팩터 값·해석·조건 사유 및 provenance에 접근할 수 있다.
- 한국어와 영어를 검증한다.
- 필수 viewport, 200% 확대, 키보드, forced colors 및 reduced motion을 검증한다.
- 잘못된 필터, 빈 결과, unavailable, integrity failure 및 not found E2E가 통과한다.
- 타입 검사, 린트, 단위 테스트, 프로덕션 빌드 및 Playwright 전체 회귀가 통과한다.
- 외부 데모 URL에서 기준 viewport의 실제 브라우저 시각 검수를 완료한다.

## 16. 명시적 제외 범위
