## Protected observation

Keep the D4 three/four-file layouts unchanged. The admitter's protected state root
holds immutable frontier records and full canonical D5 observation bytes as an
operational checkpoint. This is internal state, not a new D4 approval schema or
provider acquisition permission. Root ownership, ancestry, ACL, link/mode, copy,
fsync/no-replace and descriptor-revalidation rules must match the artifact boundary.
Its owner must match the separate admitter principal, never the producer principal.

The observation hash remains exactly D5's existing prefix plus sorted canonical
FileEvidence array. No timestamp, release, salt or error string enters that hash.
A fixed canonical record binds Owner, policy, admission, protected civil range,
the previous frontier hash and the exact observation hash/count. Reader checks bind
it to an opaque sealed input and expected receipt hash; arbitrary JSON alone never
creates a protected expected-observation capability.

The first record comes only from the independent verifier's retained complete
discovery. Continuation compares a freshly captured full observation for every
already sealed range against the protected record, then unions the new complete
session observation. Exact evidence replays. Added, removed or changed observations
touching sealed ranges block, even if selected numeric values are unchanged.
All equivalent calendar witnesses remain represented, not only D4's selected one.
Do not reseal old dates merely because a release changed.

Attributable failures use the fixed source event codes and expected/observed
FileEvidence commitment. An unattributable snapshot/parse/IO failure produces a
typed INPUT_BLOCKED poll outcome without a fabricated permanent event hash. The
SQL adapter must commit BLOCKED outcomes and resolve uncertain commit replies by
receipt. No data-only frontier API can grant the guarded DB authority.

Durable admission files and the matching protected frontier are both required
before the adapter submits the SQL admission. Failed staging may leave an invisible
orphan, never a successful receipt. No existing sealed evidence is deleted or
overwritten. Poll-state freshness, full role isolation and runtime activation remain
later integration gates. Bound cumulative observation bytes/files and chain work;
reject exceeding inputs rather than truncate evidence.
