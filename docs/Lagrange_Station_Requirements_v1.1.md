# 1. 프로젝트 개요

## 1.1 배경

Lagrange Station은 소유자와 지인 4~5명이 사용할 수 있는 초대 기반 개인·소규모 퀀트 투자 플랫폼을 구축하는 것을 목적으로 한다. 사용자는 정해진 규칙에 따라 산출된 **후보 종목, 종목별 점수, 목표 비중**을 확인하고, 동일 규칙을 과거 데이터에 적용한 백테스트 결과와 가상 포트폴리오 성과를 검토한다.

Lagrange Station은 “엔진이 알아서 좋은 종목을 추천하는 서비스”가 아니다. 종목 선정 기준은 전략으로 명시하며, 별도의 연구·선정 계층이 팩터 계산과 순위화를 수행한다. NautilusTrader는 선정된 전략과 목표 비중을 과거 데이터, 가상시장 또는 실제 시장에서 실행하고 주문·체결·포트폴리오 상태를 관리하는 주 엔진으로 사용한다.

## 1.2 프로젝트 명칭 및 제품 정의

> **Lagrange Station은 시장 데이터를 수집·검증하고, 규칙 기반 후보 종목과 목표 비중을 산출하며, 이를 재현 가능한 백테스트·가상투자·제한된 실거래로 연결하는 초대 기반 개인·소규모 퀀트 플랫폼이다.**

공식 프로젝트명은 **Lagrange Station**, 단축명은 **Lagrange**, UI 표시명은 **LAGRANGE**, 내부 식별자는 `lagrange`, 저장소 루트는 `lagrange-station`으로 한다. 명칭은 여러 힘의 균형점이라는 이미지처럼 데이터·전략·포트폴리오·리스크·실행을 한 지점에서 조율한다는 의미를 갖는다. UI에서는 일상적 표현으로 “종목 추천”을 사용할 수 있으나, 시스템 내부 용어와 데이터 모델에서는 `Recommendation`을 **전략 기반 후보 및 목표 비중 제안**으로 정의한다.

## 1.3 핵심 결정

1. NautilusTrader를 주 백테스트·Paper·Live 엔진으로 사용한다.
2. 종목 선정과 팩터 연구는 NautilusTrader 외부의 `Research & Selection` 계층에서 수행한다.
3. LEAN은 MVP 필수 구성요소가 아니다. 대규모 미국 주식 유니버스, 복잡한 옵션·선물 연구 또는 교차 검증의 실익이 확인될 때 독립 워커로 추가한다.
4. MVP는 일봉 기반, 롱 온리, 시장가 중심, 주간·월간 리밸런싱으로 제한한다.
5. 4~5명의 사용자는 종목 후보 조회, 백테스트, 가상투자를 사용한다. 타 사용자의 실계좌 자동주문은 초기 범위에서 제외한다.
6. 실제 주문은 우선 소유자 본인의 계좌만 후속 단계에서 연결한다.
7. 엔진 코어는 초기에는 포크·대규모 수정하지 않고, 어댑터·전략·커스텀 데이터 계층으로 확장한다.

# 2. 목표와 성공 기준

## 2.1 비즈니스·사용 목표

- 사용자가 전략의 규칙과 추천 근거를 이해할 수 있어야 한다.
- 과거 성과뿐 아니라 최대 낙폭, 비용 민감도, 과최적화 가능성을 함께 확인할 수 있어야 한다.
- 동일한 데이터·전략·설정으로 동일 결과를 재현할 수 있어야 한다.
- 백테스트에서 검증된 전략을 가상투자로 옮길 때 전략을 전면 재작성하지 않아야 한다.
- 실제 주문 단계에서는 중복 주문, 오래된 데이터, 잔고 불일치와 같은 운영 오류를 보수적으로 차단해야 한다.

## 2.2 MVP 성공 기준

| ID | 성공 기준 |
|---|---|
| SC-01 | 초대 사용자 5명이 서로의 전략 설정·백테스트·가상계좌 데이터를 볼 수 없도록 격리된다. |
| SC-02 | 고정 ETF 유니버스 10~30개에 대해 월간 모멘텀 전략을 10년 이상 일봉으로 백테스트할 수 있다. |

| SC-09 | 모든 백테스트는 데이터 버전, 전략 버전, 엔진 버전, 설정 해시를 기록한다. |

# 3. 사용자와 역할

| 역할 | 설명 | 주요 권한 |
|---|---|---|
| Owner/Admin | 소유자이자 개발·운영 관리자 | 사용자 초대, 데이터셋 승인, 전략 코드 등록, 작업 관리, 본인 실계좌 연결, Kill Switch |
| Member | 초대된 공동 사용자 4명 내외 | 허용된 전략의 파라미터 설정, 추천 조회, 백테스트 실행, 개인 가상계좌 사용 |
| Worker/System | 배치·백테스트·리포트 실행 주체 | 데이터 처리, 전략 실행, 결과 저장. 사용자 인터랙티브 로그인 권한 없음 |

## 3.1 권한 원칙

- 공개 회원가입을 제공하지 않는다.
- 사용자는 본인의 전략 설정, 백테스트 결과, 추천 구독, 가상 포트폴리오만 조회·변경한다.
- 전략 코드 등록과 데이터셋 승인 권한은 Owner/Admin에게만 부여한다.
- Member가 임의 코드를 업로드해 서버에서 실행하는 기능은 MVP에서 제공하지 않는다.
- 실거래 자격증명은 Owner/Admin도 화면에서 원문을 재조회할 수 없도록 저장한다.

# 6. 주요 사용자 시나리오

## UC-01 전략 기반 후보 종목 조회

1. 사용자가 전략과 파라미터를 선택한다.
2. 시스템은 기준일 당시 사용 가능한 후보군을 구성한다.
3. 유동성·추세·모멘텀 등 팩터를 계산한다.
4. 필터와 점수식을 적용해 상위 종목을 선택한다.
5. 포트폴리오 제한을 적용해 목표 비중을 생성한다.
6. 사용자는 종목별 점수, 선정·제외 이유, 데이터 기준 시각을 확인한다.

## UC-02 백테스트 실행

1. 사용자가 전략 버전, 기간, 초기자금, 비용 설정, 벤치마크를 선택한다.
2. 시스템은 데이터셋 상태와 파라미터를 검증한다.
3. 작업을 대기열에 등록한다.
4. 격리된 NT Backtest Worker가 과거 이벤트를 순서대로 재생한다.
5. 결과와 로그, 주문·체결 내역, 재현 메타데이터를 저장한다.
6. 사용자는 리포트를 조회하고 다른 실행과 비교한다.

## UC-03 전략 견고성 검사

1. 사용자가 기준 백테스트를 선택한다.
2. 시스템은 파라미터 주변값, 비용 증가, 검증 구간 변경을 자동 실행한다.
3. 결과가 특정 파라미터나 특정 기간에 과도하게 의존하는지 계산한다.
4. 전략 안정성 경고와 근거를 표시한다.

## UC-04 가상투자

1. 사용자가 검증된 전략을 개인 가상계좌에 연결한다.
2. 장 마감 후 목표 비중이 갱신된다.
3. 다음 거래일 시가 또는 모의 체결 규칙으로 가상 주문·체결이 생성된다.
4. 현금·포지션·비용·성과를 사용자별로 기록한다.

## UC-05 소유자 본인 계좌 실거래

1. Owner가 검증된 전략을 실거래 후보로 승격한다.
2. 주문 전 Risk Gateway가 데이터 신선도, 최대 금액, 종목별 한도, 중복 주문을 검사한다.
3. NT Live Node와 KIS Adapter가 본인 계좌로 주문을 전달한다.
4. 주문 결과가 불명확하면 즉시 재주문하지 않고 주문 상태를 조회한다.
5. 시작 시점과 실행 중에 주문·체결·잔고 대사를 수행한다.
6. 비정상 상태에서는 Kill Switch가 신규 주문을 차단한다.

## 8.3 Point-in-time 원칙

- 후보 종목 목록은 해당 과거 날짜에 상장되어 있던 종목만 포함한다.
- 재무 정보는 `published_at` 이후에만 전략 입력으로 사용할 수 있다.
- 상장폐지 종목을 데이터에서 제거하지 않는다.
- 현재 지수 구성 종목을 과거 전체 기간에 그대로 적용하지 않는다.
- 가격 정정이 발생하면 새 데이터 버전을 만들고 기존 결과를 보존한다.

# 9. 백테스트 정확성 규칙

## 9.1 시간 규칙

MVP의 표준 체결 규칙은 다음과 같다.

1. T일 장 마감 후 T일 종가와 과거 정보로 신호를 계산한다.
2. 전략은 즉시 체결하지 않고 `PendingTarget`을 저장한다.
3. T+1일 세션 시작 이벤트에서 당일 시가만 전략·체결 계층에 공개한다.
4. 주문 수량과 비용을 계산하고 T+1일 시가에 슬리피지를 적용해 체결한다.
5. T+1일 종가 이벤트에서 포트폴리오를 평가한다.

NautilusTrader에는 네이티브 “다음 봉 시가” 모드가 없으므로, 일봉 원본을 **세션 Open 커스텀 이벤트와 장 마감 Bar 이벤트로 분리**해 미래 정보 노출을 방지한다.

## 9.2 가격 사용 정책

- 신호용 지표는 전략 정의에 따라 수정 가격 또는 Total Return 기준 가격을 사용할 수 있다.
- 실제 체결 가격은 원시 시가에 비용과 슬리피지를 적용한다.
- 액면분할은 포지션 수량과 가격 기준을 조정한다.
- 배당은 지급일 또는 정의된 모델에 따라 현금 장부에 반영한다.
- 기업행사 정보가 없는 데이터셋은 개별주식 장기 백테스트에 “정확도 제한”을 표시한다.

## 9.3 거래 비용

기본 비용 모델은 다음 항목을 독립적으로 설정한다.

- 매수·매도 수수료율
- 최소 수수료
- 매도 관련 세금
- 고정 basis point 슬리피지
- 최소 거래금액
- 리밸런싱 비중 차이 임계값

표준 체결 가격 예시는 다음과 같다.

- 매수: `open × (1 + slippage_rate)`
- 매도: `open × (1 - slippage_rate)`

## 9.4 성과 해석 원칙

- 단순 수익률만으로 전략을 승인하지 않는다.
- 전략 성과는 벤치마크와 동일 기간·통화 기준으로 비교한다.
- 비용과 체결 가정을 제거한 결과는 연구 참고용으로만 표시한다.
- 전체 기간 최적 파라미터를 같은 기간 성과로 제시할 때 과최적화 경고를 표시한다.
- 최종 검증 구간은 전략 선택 과정에서 수정하지 않는다.

# 11. 법적·운영 경계

- 4~5명 사용 자체는 기술적으로 문제되지 않지만, **타인의 실제 계좌에 주문 서비스를 제공하는 행위**는 단순 개인용 자동매매와 다른 운영·계약·규제 검토가 필요하다.
- KIS 개인 고객 API는 본인 자산과 본인 전략 매매 용도로 구분되며, 제3자 서비스 제공은 별도의 제휴 대상 안내가 적용된다.
- 따라서 Member에게는 MVP와 Paper 단계에서 실제 계좌 연결 기능을 제공하지 않는다.
- 타인에게 표시할 시장 데이터와 재무 데이터는 공급원별 저장·가공·재배포 권한을 확인한다.
- 화면에는 성과가 미래 수익을 보장하지 않으며, 전략 기반 연구 결과라는 점을 명확히 표시한다.

# 12. 수용 테스트

## 12.1 핵심 E2E 테스트

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| AT-01 | Member A가 백테스트를 만들고 Member B가 ID를 추측해 조회 | 403 또는 404, 데이터 노출 없음 |

| AT-03 | 동일 입력을 두 번 실행 | 동일 거래·Equity Curve·지표 또는 기존 실행 재사용 |
| AT-04 | 수수료와 슬리피지를 증가 | 최종 자산이 감소하고 비용 합계가 거래 내역과 일치 |
| AT-05 | 특정 종목 일봉 누락 | 추천·백테스트가 경고 또는 차단 정책대로 동작 |

| AT-07 | 사용자별 Paper 계좌에서 동일 전략 실행 | 주문·현금·포지션이 계좌별 독립 유지 |
| AT-08 | 오래된 데이터로 Live 주문 시도 | 주문이 차단되고 사유와 감사 로그 생성 |
| AT-09 | KIS 주문 응답 타임아웃 후 동일 의도 재시도 | 주문상태 조회 후 처리하며 중복 주문 없음 |

## 12.2 기준 전략 골든 테스트

고정된 소형 데이터셋과 전략 설정으로 다음 산출물을 골든 파일로 보존한다.

- 추천 종목·점수·목표 비중
- 주문·체결 목록
- 일별 현금·포지션·총자산
- 비용 합계
- 성과 지표
- 데이터·전략·엔진 버전

엔진 또는 데이터 변환 로직을 업그레이드할 때 결과 차이를 자동 비교하고, 승인되지 않은 변화가 있으면 배포를 차단한다.

# 13. 릴리스 단계

## Phase 0 — 기술 검증

- NautilusTrader 설치와 버전 고정
- ParquetDataCatalog 적재
- ETF 3~5개, 단순 이동평균 전략
- T일 종가 → T+1일 시가 이벤트 모델 검증
- 주문·체결·Equity Curve 골든 테스트

**종료 기준:** 미래 정보 참조 없이 기준 전략이 반복 재현된다.

## Phase 1 — MVP 추천·백테스트

- 초대 인증, 사용자 격리
- ETF 10~30개 데이터 파이프라인
- 팩터 엔진과 Selector
- 4개 기본 전략
- 백테스트 대기열·리포트·비교
- 데이터 품질·감사 로그

**종료 기준:** 사용자 5명이 추천 조회와 백테스트를 안정적으로 사용한다.

## Phase 2 — 가상투자

- 사용자별 Paper 계좌
- 장 마감 추천 스케줄
- 다음 거래일 가상 주문·체결
- 알림과 일별 성과

**종료 기준:** 최소 한 전략이 백테스트와 Paper에서 동일한 신호 규칙으로 운영된다.

## Phase 3 — 소유자 실거래

- KIS Adapter
- Risk Gateway, Kill Switch
- 주문 멱등성·재접속·대사
- 소액 본인 계좌 운영

**종료 기준:** 장애·타임아웃·재시작 테스트에서 중복 주문과 장부 불일치가 방지된다.

## Phase 4 — 확장

- 한국 개별주식 동적 유니버스
- Point-in-time 재무 팩터
- 분봉·틱·호가 전략
- LEAN 독립 연구 워커 평가
- 필요 시 순수 Rust NT 경로 확대
